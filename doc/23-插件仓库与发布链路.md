## 一、现状（2026-10-16 盘点，别重做）

1. **机制已完成**：manifest 校验、A 面 iframe + CSP 响应头、B 面 QuickJS-WASM 沙箱、宿主 API v1、装 / 更新 / 回退 / 卸、装后即生效、许可证与授权态。`plugintest` 76 条。
2. **打包已完成**：`npm --prefix server run packplugin -- <目录> [输出] [私钥]` → `.umbraplugin`（gzip 过的 JSON 容器，`format: 1`，`files` 为路径→base64，`signature` 为对 `canonical()` 的 Ed25519 签名，见 `server/src/plugin/pack.ts`）。
3. **钥匙**：Studio 验包和验许可证用的都是 `keys/publisher.pub`（`pack.ts` 与 `license.ts` 同一个 `publisherKeyPath()`）；服务端签许可证用的是 ECS 上的 `data/plugin-publisher.key`（`Umbra/private_ai_assistant/plugin_licenses.py`），注释写明公钥即复制到 Studio `keys/publisher.pub`。**所以服务端拿同一把私钥签包，Studio 不用改就能验**。

## 二、目标形态

### 2.1 仓库

**仓库地址：https://github.com/TestEngineerFish/umbra-plugins**（私有，`main` 分支；SSH `git@github.com:TestEngineerFish/umbra-plugins.git`）。
插件源码、SDK、打包脚本的正本都在那边；Studio 只经 `npm --prefix server run sync-plugins` 拉三个内置插件的包（§四）。

```
umbra-plugins/
  README.md                 ← 给人和给 AI 的总入口：怎么新建一个插件、怎么打包、怎么验
  sdk/
    umbra.js                ← 插件侧桥，唯一出处（从 Studio runtime/umbra-plugin.js 收口）
    theme.css               ← 设计 token，唯一出处
    manifest.schema.json    ← 从 server/src/plugin/manifest.ts 导出的 JSON Schema
    PLUGIN-SPEC.md          ← 写插件的规范（§二·3），AI 开工前必读
    PACKAGE-FORMAT.md       ← .umbraplugin 容器与 canonical() 规则 + 测试向量（给服务端 Python 对拍）
  plugins/
    com.umbra.markdown/     ← 一个插件一个目录，目录名 = manifest.id；**不再嵌版本号子目录**，版本在 manifest 里
    com.umbra.code/
    com.umbra.html/
    com.umbra.yaml/ …
  scripts/
    pack.mjs                ← 打包：先把 sdk/umbra.js、sdk/theme.css 拷进插件目录再打（vendor 时机），输出 dist/<id>-<version>.umbraplugin（**不签名**）
    validate.mjs            ← 校验 manifest 合 schema、能力名带前缀、B 面不含 import 外部模块、A 面入口存在
    sync-studio.mjs         ← 给 Studio 用：把三个内置插件解包到 Studio 的 plugins/<id>/<version>/（§四）
  .github/workflows/
    ci.yml                  ← PR：validate + pack 全部插件；tag：把 dist/*.umbraplugin 挂到 Release
```

### 2.2 一份 SDK，vendor 时机在打包

插件目录里**不提交** `umbra.js` / `theme.css`（`.gitignore` 掉），`scripts/pack.mjs` 打包时从 `sdk/` 拷入。
这样三份分叉的问题从结构上消失；Studio 侧宿主契约升级时，改一处、全部重打。

### 2.3 `PLUGIN-SPEC.md` 必须写明的硬约束（AI 不知道这些会写出跑不了的插件）

- B 面在 **QuickJS** 里跑：没有 `WebAssembly`、`fetch`、`fs`、`require`、`process`、`Buffer`；无 JIT，纯计算比 V8 慢一个量级。重计算放 A 面或回调宿主。
- **不许起子进程**（`20` P1），manifest 没有 `exec` 槽位。
- 读写文件**只能** `host.call("read_file" | "write_file" | …)`；能力名**必须**以插件 id 为前缀。
- 资源有限额（内存 / 一次调用时限 / 二进制读取上限 / 文本读取上限，用户在设置里调，`20` §3.6）：B 面读 `host.limits`、A 面读 ctx 的 `limits`；大文件用 `read_file` 的 `byteOffset` / `byteLength` 分段读（不给 sha256；`encoding` 只能不给或给 `"base64"`，给别的回 `E_BAD_INPUT`）。
- A 面是 `sandbox="allow-scripts"` 的 iframe + CSP `default-src 'none'`：画不到矩形外，菜单 / toast 走 `umbra.menu` / `umbra.toast` 由宿主代画；**不能外联**。
- `kinds[].priority` 封顶 95；**非内置插件不能认领内置类型**（`.dc.html` 等）。
- 包内二进制走 base64（+33%），单包上限 50 MB（下载侧硬限）。vendor 的第三方库要算进去。
- 宿主 API 以 `hostApi: "^1"` 对版本；新插件一律写 `"^1"`。

## 三、服务端与后台（Umbra 仓库）

### 3.1 新接口

| 接口 | 做什么 |
| --- | --- |
| `POST /admin/plugins/{id}/package`（multipart，字段 `file`） | ① 解包（gzip → JSON，`format` 必须为 1）② `manifest.id == {id}`，否则 400 `id_mismatch` ③ 版本必须比表里的高（semver），否则 409 `version_not_newer` ④ 用 `plugin_licenses.py` 那把私钥对 `canonical()` 签名，写回 `signature` ⑤ 重新 gzip，存 OSS `umbra-assets` 桶 `plugins/{id}/{version}.umbraplugin` ⑥ 从 manifest 回填表里的 `version` / `formats`（kinds[].ext 展开）/ `permissions` / `tools`（有 B 面才有）/ `size` / `updated`；`package_url` 写成 `https://<API 域名>/plugins/{id}/package?v={version}` ⑦ 回 `{plugin, signed: true, bytes}` |
| `POST /admin/plugins/package`（multipart，不带 id） | 「从包新建」：同上，但 id 取 manifest 的；新建的条目 `status = unlisted`、`price = 0`，后台看一眼再上架 |
| `GET /plugins/{id}/package?v=` | **不要凭证**（市场登录前就能装免费的；收费的靠许可证挡，不靠下载挡）。从 OSS 内网取流回，`Content-Type: application/octet-stream`，`Content-Disposition` 带文件名；没 `v` 取表里当前版本。顺手记一条下载计数（`plugin_downloads` 表或日志，二选一，不做成功能） |

### 3.2 `canonical()` 的 Python 对拍 —— 这条是承重的

签名签的是 `canonical()` 的字节：`JSON.stringify({format, manifest, files})`，`files` 按键排序，`manifest` 保持包里的键序，无空格、非 ASCII 不转义。
Python 侧：`json.dumps(obj, separators=(",", ":"), ensure_ascii=False)`，`manifest` 用 `json.loads` 的原序（dict 保序），`files` 用 `sorted(keys)`。
已知的跨语言差异点：浮点（JS `1.0` → `1`，Python 保留 `1.0`；manifest 里不该出现浮点，校验时拒绝）、astral 字符的键排序（JS 按 UTF-16 code unit，Python 按 code point；文件名限 ASCII 即可回避，`validate.mjs` 加这条）。
**测试必须有**：用 `sdk/PACKAGE-FORMAT.md` 里的测试向量（一个最小包 + 它的 canonical 字节的 sha256 + 用测试私钥签出的签名），Python 签出来的要和向量一致；反向用 Studio `verifyPackage` 验一遍 Python 签的包。

## 七、验收（闭环走通的定义）

1. `umbra-plugins` 打 tag → CI 产出 10+3 个未签名包
2. 后台「从包新建」传一个新格式包 → 表里出现条目（unlisted）→ 拨上架
3. Studio 市场看到它 → 装 → 验签通过（**不是** dev 放行）→ 打开对应文件由插件画 → AI 能调它的 B 面能力
4. 后台「上传新版本」传同 id 更高版本 → Studio 市场显示可更新 → 更新 → 回退
5. 三个内置的：Studio 打包后 `plugins/` 下是从 Release 解出来的；市场里有包；能走 4
6. 断网：已装的都能用，市场回落缓存

### 7.2 留给人跑的（要线上服务端，非 dev 模式）

前置：Studio 用这个分支的构建；**不设** `UMBRASTUDIO_PLUGIN_DEV`；`keys/publisher.pub` 是线上那把真公钥。

- [ ] **新格式**：后台「插件」页 →「从包新建插件」选 Release v0.2.0 里的包（可多选）→ 表里出现、默认下架 → 拨上架
  - 2026-10-17 查线上：13 个包**都已经传上去了**（10 个新格式 + 3 个内置），`pdf` / `tex` 已上架，其余下架。这一步可以直接从「拨上架 yaml」开始
- [ ] Studio 首页「商城」→ 看到 YAML 编辑（不用刷新缓存：商城每次打开当场问服务端）→ 购买 / 领取并安装 → 「已装」里**没有**「未签名」标签（= 线上签名验过了，不是 dev 放行）
- [ ] 在一个项目里放 `a.yaml` → 点开由插件画 → 对会话说「列出 a.yaml 的键路径树」→ AI 调 `yaml__outline`
- [ ] **新版本**：umbra-plugins 里把 yaml 的 version 改 1.0.1、打 tag → 后台该行「上传新版本」传新包 → Studio 市场该条出现「有新版本」圆点 → 更新 → 「已装」里切回 1.0.0 → 再切回 1.0.1
- [ ] **内置升级**：umbra-plugins 里把 markdown 的 version 改 1.0.1、打 tag → 后台 `com.umbra.markdown` 那一行（服务端预置的内置条目，2026-10-17 查线上：三个内置都在、`builtin=1`、已放 1.0.0 的包、**下架中**）点「上传新版本」传 1.0.1 → 拨上架 → Studio 市场 Markdown 详情页出现「更新到 1.0.1」→ 点 → 「已装」里显示「已升级（出厂 1.0.0）」、没有「未签名」→「退回出厂版本 1.0.0」
  - 注：三个内置条目**下架时**市场不列它们，Studio 里它们照常作为内置插件用；要走市场升级就得上架。
- [ ] **打包**：`npm --prefix shell run dist` → 打包日志里先出现「同步内置插件」→ `npm --prefix shell run packtest` 过（`core/plugins/<三个 id>/<版本>/` 都在）
- [ ] **断网**：断网后打开 Studio → 已装的都能用 → 商城显示「这是上次联网时的目录」
