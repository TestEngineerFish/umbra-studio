# 给 plugins 的改动说明：把 `#encbar` 与 `ud-diff-changed` 纳入契约

> 来由：Studio issue #193 甲类（插件编辑区 18 条红 + 1 次超时退出）查完。
> **结论先说：那 18 条红不是插件的缺陷，用户碰不到。** 下面只有一件要你们做，而且很小。

---

## 一 · #193 甲类的根因（三条症状，一个共因，都在判据侧）

| 症状 | 根因 | 用户会碰到吗 |
| --- | --- | --- |
| `#encbar` 编码横条没出来 | **判据侧级联** | ❌ 不会 |
| 工具条上没有「源码 / 树」 | 同上 | ❌ 不会 |
| diff 标记 0 行（`.cm-line.ud-diff-changed`） | 同上 | ❌ 不会 |

**共因**（Studio `uitest` 自己的注释已经记着，这次查证实了）：
`uitest` 的清理按**文案**点「放弃改动」，而 **kit 1.2 起那颗按钮会先弹一次 `umbra.menu` 二次确认**
（CHANGELOG 里写着，是有意改的）。判据点了它却不选菜单项 → 脏状态一直留着 →
下一次点文件弹「要切走吗」确认卡 → **遮罩挡住后面所有点击** →
「只读」「编码」「源码 / 树」三族全红，而红的原因和它们自己毫无关系。

> **一个被 catch 吞掉的点击失败，和一个「点成功了但没走完」的流程，症状一模一样。**

另一半是 `#dirty` / `#draft` 这类 id 是 Studio 判据**自己猜的**，插件侧零命中 ——
那一半你们已经修了：**kit 1.1.0 的 `data-kit-*` 契约 + `kit-contract.json` 冻结清单 +
`kit.test.mjs` 那道闸**。Studio 的判据同一天改成按 `data-kit-action` 点。

## 二 · 为什么能确定「用户碰不到」（量出来的，不是推断）

1. **功能一直都在**：`bar.id = "encbar"` 和 `ud-diff-changed` 在
   `plugins/com.umbra.code/app.mjs` 里**从第一个提交（`0200b00`）就有**，
   `git log -S` 全程只有那一次新增，从没被删过。
2. **kit 1.1.0 只加属性**：那次 diff 里每一处都是
   `$el("div","uk-find")` → `kit($el("div","uk-find"),"find-panel")` ——
   **类名和 DOM 层级一个字没动**（提交信息里也这么写）。所以可见产品没变过。
3. **出事那天装的是 `com.umbra.code` 1.3.0**（2026-10-20 W7-1），三样它都有。
4. **今天手动复现三个面，全是好的**（Studio 侧独立探针，不走 `uitest` 的选择器）：
   · `#encbar` → 「按 UTF-8 解出 6 个乱码字符（占 35.3%）—— 多半不是 UTF-8 / 按 GBK 重读 / 按 GB18030 重读」
   · 工具条 → 「源码 / 树 / 对比上一版 / 选中行给 AI」
   · 坏 `.json` → 行标记 1 处（一处语法错 → 一行，对）
5. Studio 今天整套 `uitest` **464/466**，甲类那 18 条全绿。

## 三 · ⚠️ 要你们做的那一件（小）

**`#encbar` 和 `.cm-line.ud-diff-changed` 不在任何契约里** ——
`sdk/kit-contract.json` 里两个都是 0 命中（它们是 `com.umbra.code` 自己的内部 DOM）。
而 Studio 的 `uitest` 今天**仍然按这两个内部名字找**（`app/uitest.mjs:3678` / `3908` / `4389`）。

> **这正是 #193 甲类的那个形状没被完全消除的那一半**：
> 判据依赖的是插件的内部 DOM，而内部 DOM 本来就是你们可以随时改的。
> 改名那一天，Studio 会再红一次 18 条，而原因又和它们自己无关。

**建议**（你们定怎么落）：

| 选项 | 做法 |
| --- | --- |
| **甲（推荐）** | 把这两样纳入 `kit-contract.json` 一类的冻结清单 —— 它们不在 kit 里，可以是 `com.umbra.code` 自己的一份（比如 `plugins/com.umbra.code/contract.json`），由它自己的自测对着查。名字建议 `data-kit="enc-bar"` / `data-kit-mark="diff-changed"`，和 kit 的命名一族 |
| 乙 | 明说「这两个是内部 DOM，不许依赖」，并给出等价的契约出口（哪怕只是一个 `data-*` 标记）|
| 丙 | 什么都不做，而把「改了内部 DOM 要通知 Studio」写进你们的 CHANGELOG 纪律 |

⚠️ **选甲或乙都要告诉我新名字**，Studio 侧改 3 处选择器（`uitest` 里，产品代码零改动）。
选丙我就在 `uitest` 那两处加一句注释说明它依赖的是内部 DOM，并接受它会偶发。

## 四 · 不用你们做的

· 三条症状**都不要修**，它们没坏。
· kit 的 `data-kit-*` 契约这件你们做得比我们要求的更到位
  （冻结清单 + 变异验证过的闸），Studio 侧已经全部改过去了。
· #193 甲类里那条「判据抛出去带走整个脚本」是 Studio 判据层的事（M17-2），和你们无关。
