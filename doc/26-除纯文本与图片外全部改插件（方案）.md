# 除纯文本与图片外全部改插件 —— 方案

> **来由**：sam 2026-10-23 定的产品边界（经 geek-99 转达）。
> 「不应该有『内置插件』这个说法。应用本身只带最基础的查看能力：任何文本类型的文件都能打开，
> 按纯文本展开，不管格式；图片能显示就显示，做不到就不支持，要看就去下载插件。其他的一律走插件。」
>
> 范围：**除纯文本和图片，全部改成插件** —— 三个出厂插件（`com.umbra.markdown` / `com.umbra.code` /
> `com.umbra.html`）变成商城里的普通插件，`.dc.html` 设计稿、`media-video` / `media-audio` 也在内。
>
> 本文**只是方案**，一行代码都没改。技术上能定的直接定了（标【定】），产品取舍列成选项（标【选】）。

---

## 〇 一句话结论

**宿主侧要做的事比看起来少，而 `.dc.html` 那一块做不到 sam 说的那个样子** —— 不是工作量问题，
是「插件为什么安全」这条理由本身挡着（§二）。

两条实测出来的好消息：

| 已经成立的 | 证据 |
| --- | --- |
| **「任何文本都按纯文本展开」宿主已经有了** | M14-11 做的嗅探（前 8 KB 无 NUL + `U+FFFD` ≤ 10%）+ `asText: true` 出路 + 超限给开头一段；`fallback-card.tsx` 已经在显示正文 |
| **「没装插件时 `.md` 能看」今天就是这样** | `shell/beforePack.cjs` 那道闸的注释自己写着：不跑 `sync-plugins` 打出来的包「打开 .md **只有通用文件卡**」—— 而通用文件卡**是带正文的** |

所以这件事的主体不是「写一个纯文本查看器」，是**把三类特权拆掉**：
① `plugins/` 住在 `TOOL_ROOT`（只读、卸不掉）· ② 内置插件能认领内置 kind · ③ 打包时缺一个就拒绝打包。

## 一 现在应用自带什么，逐项裁决

### 1.1 前端格式模块 `app/src/kinds/`

| 模块 | 认领的 kind | 裁决 | 理由 |
| --- | --- | --- | --- |
| `dir/` | `dir` | **留** | 目录树是工作台本身，不是一种文件格式 |
| `fallback.tsx` + `fallback-card.tsx` | `other` | **留** | 这是「任何文件都能打开」那句话的实现，也是注册表的兜底 |
| `image/` | `image` | **留**（编辑那一半见【选 A】） | sam 明确说图片留下 |
| `media.tsx` | `media-video` / `media-audio` | **搬进插件** | sam 明确点名 |
| `dc/` | `dc` | **见 §二** | 最难的一块，单独谈 |
| `plugin/` | — | **留** | 它是插件的宿主（A 面 Surface / chrome / loader），不是格式模块 |

【选 A】**图片编辑（裁剪）留不留？** sam 的原话是「只带最基础的**查看**能力」。
`image/Edit.tsx` + `Save.tsx` 是 #108 做的裁剪与另存（+18.7 KB gzip）。
- **A1 留下**：它已经做完、判据齐、体积小，而「看图顺手裁一下」是常见动作。
- **A2 搬进一个图片插件**：严格贴合「只带查看」。代价是一份做好的能力要重做一遍 A 面，
  而**裁剪要拿到像素**（`canvas.toDataURL()`），插件 iframe 没有 `allow-same-origin`，
  它**读不到画布** —— 要么宿主开一件新的白名单能力把像素递进去，要么这功能就没了。
- ⚠️ **我建议 A1**，理由不是省事：A2 会让「图片能显示就显示」这条承诺变成「能显示但不能动」，
  而用户看不出裁剪为什么要单独装一个插件。

### 1.2 内置 kind 表 `server/src/shared/kinds.ts`

现在 `BUILTIN_KINDS` 共 10 条。裁决的关键是把两件事分开：

> **kind 认定是「这个文件叫什么」（词汇），不是「我能拿它干什么」（能力）。**
> 前者该留在宿主，后者该跟着插件走。

| kind | priority | 裁决 | 说明 |
| --- | --- | --- | --- |
| `dir` / `other` | -1 / -2 | **留** | 兜底，不是格式 |
| `image` | 80 | **留** | |
| `md` / `json` / `html` / `code` | 90 / 70 / 60 / 10 | **留条目，去掉「只有 bundled 能认领」的特例** | 留着它们，`.md` 在树里才有「≡ Markdown」这个名字和图标，而且 `textual: true` 让服务端**不必嗅探**就知道按文本读 |
| `media-video` / `media-audio` | 5 / 5 | **删条目，改由插件带 `ext` 声明** | 它们的 priority 已经压到 5（低于插件默认 50），说明当初就是为了「等插件来了让位」而设的 —— 现在插件来了 |
| `dc` | 100 · `claimable: false` | **见 §二** | |

【定】**`md` / `json` / `html` / `code` 的条目留下，但 `isBuiltinKind` 对它们的特权要撤**。
现在 `registerKind` 对内置 id 直接抛（`kinds.ts:190`），而 bundled 插件走一条特例绕过它。
改成：**这四种标 `claimable: true`，任何插件都能认领**（`dc` 的 `claimable: false` 保留，见 §二）。
⚠️ 这会解开 `doc/00` §172.6 记着的那个坑的反面 —— 当时的问题是「内置类型只有 bundled 能认领」
会**静默弄坏第三方媒体插件**；现在正好是要撤掉那条限制。
⚠️ 撤掉之后 `PLUGIN_MAX_PRIORITY`（95）成为唯一的护栏，而 `md` 的 90 在它之下 —— **够用**。

### 1.3 `plugins/`（`BUNDLED_DIR`，`TOOL_ROOT` 下）

**整个目录取消。** 它带来的三件特权全部消失：

| 现在 | 改后 |
| --- | --- |
| `store.ts:69` `scanRoot(BUNDLED_DIR, true, factory)` 把它们当 `builtin` 加载 | 只扫 `PLUGINS_DIR`（`STATE_ROOT`） |
| `license.ts:160` 的 `state: "builtin"`（「免费且一直可用」） | 这一档删掉，它们走 `active` / `unlicensed` |
| `acquire.ts:81` 「内置插件随长尾雀一起，不用买也不用装」 | 删 |
| `builtin_upgrade.ts` 整个文件（验签 + 版本严格更高 + 不多认领内置类型）· 「卸载 = 退回出厂版本」 | **整个删掉**，它只为「内置能被市场升级」而存在 |
| `install.ts:60` 对 `BUNDLED_DIR` 里同 id 的特判 | 删 |
| `verbs.ts:54` `USABLE = ["builtin","active"]` | 去掉 `builtin` |

> **这是方案里收益最干净的一段**：删掉的代码比加的多，而且删掉的那些**全是为了一个不该存在的概念**服务的。

### 1.4 `sync-plugins` 与 `beforePack` 那道闸

| 现在 | 改后 |
| --- | --- |
| `sync-plugins` 把三个插件**解包**进 `plugins/<id>/<version>/` | 改成把**插件包**（`.udpkg`，签过名的那个容器）拉进 `shell/` 的 `extraResources`，**不解包** |
| `beforePack.cjs` 缺一个就**拒绝打包** | 按【选 B】定 |

【选 B】**出厂包里带不带插件安装包？**

- **B1 带包、默认不装**（**我推荐**）：随附三个 `.udpkg`，首次打开 `.md` 时横条上一颗「安装 Markdown 插件（本机已有，不用联网）」。
  装完它住在 `STATE_ROOT`，**和商城装的完全同构** —— 卸得掉、升级走商城、没有任何特权。
  > 这满足 sam 那句「不应该有『内置插件』这个说法」：**它不是内置插件，是一个随包分发的安装包。**
  代价：包体积 +约 300 KB（三个包压缩后），`beforePack` 的闸从「拒绝打包」降级成「缺了只警告」。
- **B2 什么都不带**：最纯粹。代价是**断网 / 没登录的用户永远装不上**，`.md` 永远是纯文本。
  ⚠️ 这一条要和 sam 确认他接受：首次启动如果没网，这个产品就只是一个纯文本阅读器。
- **B3 带包并自动装一次**：体验最好，但「自动装」会让用户在插件列表里看到三个自己没装过的东西 —— 和 B1 的区别只有一次点击，而那一次点击正是「这是插件」的唯一证据。

### 1.5 留在宿主的能力（不动）

纯文本嗅探 · `asText` 出路 · 超限截断 · 目录树 · 通用文件卡 · 版本/快照/回退 · 评论 ·
搜索 · 格式转换 · 拖拽与打开方式 · 接管 / 只读三段 · AI 通道与会话 · 插件宿主（沙箱、白名单、市场）。

## 二 `.dc.html`：能不能变成插件

### 2.1 两条硬约束（实测，不是推断）

| | sandbox | 后果 |
| --- | --- | --- |
| dc 的画布 iframe（`app/src/kinds/dc/View.tsx:164`） | `allow-scripts **allow-same-origin**` | `dc/nodes.ts` 靠它**穿透两层 iframe 读稿的 DOM** —— 点选、节点地址、属性面板、评论钉全在这条路上 |
| 插件 A 面 iframe（`app/src/kinds/plugin/Surface.tsx:256`） | `allow-scripts`，注释写着「**不给 `allow-same-origin`** —— 给了就退回普通 iframe，隔离没了」 | 只能 `postMessage` 传可序列化数据 |

**第二条**：插件宿主 API 白名单（`server/src/plugin/host.ts:25`）里**一件 `*_draft` 能力都没有**。
dc 要的 `write_draft` / `validate_draft` / `locate_node` / `set_prop` / `get_syntax_guide`
+ `design.ts` 那 9 件 token / icon / component + `build_index` / `get_index_data`，**全在白名单外**；
而白名单上的 `write_file` 对 `.dc.html` **会被写入口拒掉**（纪律①：唯一写入口）。

> **把这两条合起来**：「dc 变成插件」要么给它一个 same-origin 的沙箱 + 一大批专属白名单条目
> （那它只是**名义上**的插件，而且插件沙箱对它等于不存在），要么放弃点选与属性面板
> （那它只剩一个预览 iframe）。
> **这是产品取舍，不是技术选型。**

### 2.2 能拆的那几段（这部分是真的能做）

把 dc 按「谁在回答什么问题」拆开，`doc/00` §十的那条判准照旧好用 ——
**点了它，变的是什么**：

| 段 | 内容 | 归属 | 理由 |
| --- | --- | --- | --- |
| ① 写入口 | `write_draft`（归一化 → `@ds` 展开 → `__resources` 注入 → 节点地址 → 快照 → changelog） | **宿主，不动** | 纪律① 的全部价值在于「只有一条路」。开给插件 = 变成两条路 |
| ② 版本 / 快照 / 回退 / 变更 / 评论 | `history.ts` 里那 15 件 | **宿主，不动** | `filetest` 已经证明它们对**任何**文件成立，和 dc 无关 |
| ③ 文件管理 | `drafts.ts` 的 12 件（create / rename / move / trash / restore…） | **宿主**，但建议**改名** | 它们叫 `*_draft` 只是历史 —— `files.ts` 里已经有并行的 `file_*` 版本。**两套做同一件事**，该并成一套 |
| ④ dc 语义 | `validate_draft` · `locate_node` · `set_prop` · `get_syntax_guide` · `build_index` / `get_index_data` / `index_status` / `list_drafts` / `list_references` | **宿主留着**，对插件按白名单开放 | 它们是「这个格式的语法」，而语法必须和写入口在同一侧 —— 不然校验和落盘会分叉 |
| ⑤ 设计系统 | `design.ts` 9 件（token / icon / component / css 变量） | **可以搬**，但不是搬进 dc 插件，而是**搬进一个「设计系统」插件** | 它们读的是 `@ds` 指的那个目录，不读稿；对 dc 之外的格式也有用（`doc/11` Q62 那条解耦） |
| ⑥ 画布 UI | `dc/View.tsx` · `AddrBar` · `CommentBox` · `Pins` · `bridge.tsx` · `nodes.ts` | **卡在 §2.1 上** | |
| ⑦ S1–S10 界面稿 | `ui/` 那 11 份 | **宿主** | 它们是工作台自己的界面，不是 dc 格式的一部分（S1 是稿件索引、S8 是项目设置） |

### 2.3 我建议的边界

【选 C】**`.dc.html` 怎么办？** 三条路，我推荐 C2：

- **C1 完全插件化**：给 dc 插件开 same-origin 沙箱 + 二十来件专属白名单。
  ⚠️ **我不建议**：它把「插件是关得住的」这句话作废，而那句话是用 `plugintest` 93 条判据
  （演示插件同时是攻击样本）换来的。一个有 same-origin 的插件能读宿主页面的 DOM，
  包括另一个插件的 iframe、聊天记录、以及地址里的令牌。
  > **一个隔离机制开了一个例外，它保护的就只剩「没有例外的那些」。**
- **C2 分两段，坦率命名**（**推荐**）：
  · **预览这一段搬进插件**：`.dc.html` 本质是 HTML，`com.umbra.html` 那套（iframe 预览 + 点选元素给 AI）**已经能用**。
    让 html 插件把 `.dc.html` 也认领了 → **没装任何插件时 `.dc.html` 显示源码纯文本；装了 html 插件就能预览**。
  · **设计稿那一整套（点选节点 / 属性面板 / 节点地址 / 评论钉 / 演示态）留在宿主**，
    但**它不再是「打开 `.dc.html` 的默认方式」** —— 改成一个显式的「**设计稿模式**」入口（工具栏一颗钮 / 菜单一项）。
  > 这样 sam 那句话成立到它该成立的地方：**打开任何文件的默认行为都只有「看」**，
  > 而「这个软件最深的那种类型」变成一个**用户主动进入**的模式，不是一种悄悄生效的特权。
  代价照实说：`dc` 这个 kind 还在宿主代码里，`app/src/kinds/dc/` 那 7 个文件一个都不少。
  **它少的是「默认」，不是「存在」。**
- **C3 只留预览，设计稿那套删掉**：最贴合 sam 的字面意思，代价是 S1–S10 + 三种编辑方式
  + M8-31 三档 + M8-32 暂存区 + 节点地址那一整条线全部作废。
  ⚠️ 那是这个产品**最初的立项理由**（`doc/01`），不该由一条「不要内置插件」的边界顺带决定。

## 三 首次打开 / 断网 / 没装插件时，用户看到什么

按 **B1 + C2** 算（其他组合按同样方式推）：

| 文件 | 看到的 | 出路 |
| --- | --- | --- |
| `.txt` `.log` `.conf` 和任何嗅出来是文本的 | **纯文本正文**（宿主） | 没有出路也不需要 |
| `.md` | **纯文本正文**，顶上一条横条「Markdown 插件能把它排版、分节改、给目录 —— 本机已有安装包，装一下？」 | 一颗钮，不联网 |
| `.json` `.csv` `.ts` 等 | 同上，指向 `com.umbra.code` | 同上 |
| `.html` | 同上，指向 `com.umbra.html` | 同上 |
| `.dc.html` | **源码纯文本** + 两条横条：①「用网页预览插件看它」②「进设计稿模式」 | 两颗钮 |
| `.png` `.jpg` `.svg` | **图片**（宿主） | — |
| `.mp4` `.mp3` | 文件卡 + 大小/时长读不出就只说名字，一条横条指向媒体插件 | 要联网装 |
| 二进制未知 | 文件卡 + 「还是按纯文本打开」 | 已有 |

⚠️ **横条的话必须说清「能多什么」，不是「这个文件打不开」** —— 用户现在**已经看到内容了**，
这条横条是加分项而不是错误提示。按 `doc/00` §九十九 那条：**不把人送进空市场**；
拿不到市场目录（断网 / 没登录）时横条只说「本机有安装包」或者干脆不出。

⚠️ **S1 必须第一个做**，理由是本项目最常犯的那条：
> **判据在没有样本的时候，测的是「今天恰好没事」。**
「没装插件时能看纯文本」这件事今天**一条判据都没有**，而它是这整条边界的核心承诺。
不先把它钉住，后面每一步都在动一个没人量过的东西。
