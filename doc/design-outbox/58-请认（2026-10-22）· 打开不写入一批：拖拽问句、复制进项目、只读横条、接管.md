## 这一批是什么事

一句话：**「打开」和「接管」原来被做成了一件事，现在拆成了三段。**

起因是用户（sam）用「新建项目」打开自己的文档目录想看一份 `.md` ——
我们往他的目录里写了 **23 个文件 · 约 780 KB**，还改了他的 `.gitignore`，
而弹窗上写着「稿件不动，**只加 project.json**」。

> **「原来的文件不被改」是真的，「只加 project.json」是假的 ——
> 两句话混在一起，假的那半借了真的那半的可信度。**

修完之后，一个随手打开的目录现在有**三段递进的状态**，而**每一段都要有一句话**：

| 段 | 我们对这个目录做什么 | 界面上是什么 |
| --- | --- | --- |
| ① **只读预览** | **一个字节都不写**，连 AI 也不许写 | 顶部横条 + ［开始编辑］ |
| ② **可编辑** | 改他点名的那些文件；历史记在我们自己的目录里 | 横条退场 |
| ③ **设计项目** | 放 17 个工具文件进去（约 750 KB），`.dc.html` 能预览了 | 接管横条 + ［接管为设计项目］ |

⚠️ **三段的顺序和「一次只出一条横条」是这一批唯一的形制变化**，理由在 §3 末尾，
那一条最想请你认。

## 1. 拖拽进来的问句（工作台 · 已开着项目时把文件/文件夹拖到窗口上，落点不在文件列）

**什么时候出现**：当前在工作台（有项目开着）+ 从系统拖进文件 / 文件夹 + 落点**不在**左边文件列。
首页（没项目开着）**不问**，直接打开 —— 那里没有东西可丢，多一个问句只会让人问「不然还能干嘛」。

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 标题 | 怎么打开它？ | How do you want to open it? |
| 正文 1 | 拖进来的是 **&lt;文件名&gt;**。 | You dropped **&lt;name&gt;**. |
| 正文 1（多个时） | 拖进来的是 **N 项**（a.png · b.png）。 | You dropped **N items** (a.png · b.png). |
| 正文 2 | **打开它不会复制任何文件** —— 我们只是以它所在的位置为根来看。 | **Opening it copies nothing** — we just use the folder it lives in as the root. |
| 正文 3 | 要把它**复制进当前项目**的话，把它拖到左边的**文件列**里。 | To **copy it into this project**, drop it on the **file list** on the left. |
| 正文 4（只在宿主开不了新窗口时才出） | 浏览器里由你自己开标签页 —— 所以只有「在当前窗口打开」。 | In the browser you open tabs yourself — so only "Open in this window" is available. |
| 钮 1 | 取消 Esc | Cancel Esc |
| 钮 2 | 在新窗口里打开 | Open in a new window |
| 钮 3（主） | 在当前窗口打开 | Open in this window |

**形制**：460px 居中弹窗，三段式（标题条 / 正文 / 底部操作条），和「新建稿件」同一个外壳。

⚠️ **请你认一条**：用户原来要的是「新开窗口，还是在当前窗口里**并存**」两档 ——
**「并存」那一档我们这一期没做**（一个窗口并存多个项目是一次架构改动，单独排了 M15-1）。
所以现在是「新窗口 / 当前窗口」两档，**少的那一档照实缺着**，没拿一个假的「并存」糊上去。
并存做出来之后那一档加进来时，我们倾向**替掉**「在当前窗口打开」而不是三档并列 ——
因为并存之后「在当前窗口打开」实际做的是「**离开当前项目**」（当前项目的页签和会话视图都没了），
那是个破坏性动作，不该和「加到这个窗口」这种无损动作并列在同一行按钮里。**这一条请你裁。**

## 2. 复制进项目的确认（工作台 · 拖到左边文件列里）

**什么时候出现**：从系统拖进来的东西**落在文件列**的任一行或空白区。

⚠️ **这是整个工具里唯一一处会复制用户文件的地方**，而用户给过一条硬约束：
「**绝不重复存储用户的文件**」。它在这里成立的理由只有一条 ——
**复制是他自己点的，落点是他自己的项目目录**。所以这一屏的全部工作是**把「会复制」说清楚**。

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 标题 | 复制到这个项目里？ | Copy into this project? |
| 正文 1 | 拖进来的是 **&lt;文件名&gt;**。 | You dropped **&lt;name&gt;**. |
| 正文 2 | 放进 **&lt;目标目录&gt;** 会**复制一份**进去 —— 重名的自动顺延（`图 (1).png`），**不会覆盖**已有的文件。 | Dropping into **&lt;folder&gt;** will **copy** it there — duplicates get a suffix (`image (1).png`); nothing existing is **overwritten**. |
| 正文 3 | 原来那一份一个字节都不动。 | The original is left byte-for-byte untouched. |
| 钮 1 | 取消 Esc | Cancel Esc |
| 钮 2 | 在新窗口里打开 | Open in a new window |
| 钮 3（主） | 复制进来 | Copy it in |

目标目录的显示名：落在项目根时写「**项目根**」/ `Project root`。

**松手之前的反馈**（这一条也请你认）：

| 落点 | 画什么 |
| --- | --- |
| 一个**目录行** | 那一行描边高亮（`ring-accent` + `bg-accentSoft`） |
| 一个**文件行** | 高亮它**所在的那个目录行**（文件不是容器，但人确实会瞄着文件松手 —— 瞄歪一行就什么都不发生，那是一条「点了没反应」） |
| 树的**空白区** | 高亮整个树容器 = 项目根（和「在空白处右键 = 对项目根操作」同一个口径） |

⚠️ 第一版我们写错过：落在根级文件上时**每一行根级文件一起亮**，看上去像「会放到所有这些地方」。
现在只有**目录行自己**会亮。

**复制完的提示**（右下角 toast）：

| 情形 | 标题 | 正文 |
| --- | --- | --- |
| 全成 | 已复制 N 份 / `Copied N item(s)` | 目标目录名 |
| 部分败 | 复制了 N 份，M 份没成 / `Copied N, M failed` | 逐行「路径：原因」 |
| 整件败 | 复制不进来 / `Couldn't copy it in` | 服务端给的原因 |

⚠️ **成了几份和败了几份一定分开说** —— 一个「已复制」里藏着三份没进来，就是又一条假回执。

## 3. 只读横条 +［开始编辑］（工作台顶部 · 随手打开的目录）

**什么时候出现**：这个目录我们**从没为它存过任何旁数据**、也没有 `project.json`。
解锁一次之后**这个目录永远不再提示**。

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 文 | **只读预览** —— 这些文件不在你的项目里，所以我们默认**不动它们**（连 AI 也不行）。 | **Read-only preview** — these files aren't in your project, so by default we don't touch them (not even the AI). |
| 钮 | 开始编辑 | Start editing |
| 钮（进行中） | 正在解锁… | Unlocking… |

**形制**：齐边横条，高 32，照 S1 那条「索引过期」横条，**没新造一种**。

**解锁成功的 toast**：

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 标题 | 可以编辑了 | You can edit now |
| 正文 | **版本历史记在 Umbra 自己的目录里，原文件夹不会多出任何文件。** | Version history is kept inside Umbra's own folder — nothing new appears in your original folder. |

⚠️ 那句正文是**刻意占一次屏**的：它正是用户最初那个担心的正面答案，
而在这一批之前**界面上一个字都没有**。*用户看不到的保证等于没有保证。*
解锁那一下是说它最自然的时机 —— 他刚刚授权我们动他的文件。

**解锁失败**：标题「解锁失败」/ `Couldn't unlock`。

### 为什么不照抄 Notion（这一条最想请你认）

用户给的参照是 Notion 预览外部 `.md` 时顶部那条：

```
Read-only preview of S1-导出插件SDK与种子.md        [ Import to Notion ]
```

**而我们和它不是同一个理由**：

| | Notion | 我们 |
| --- | --- | --- |
| 为什么只读 | **能力所限** —— 它的编辑器只能改自己库里的块，那个文件不在库里，**它改不了** | **改得了**。「产物在你的目录里」是我们的定位 |
| 那颗钮做什么 | 把文件**复制**进它的库，之后你改的是副本 | **我们不复制** —— 落的只是我们自己目录里的一个标记 |

所以照抄「需要导入」是**对我们自己行为的错误描述**。
我们这道闸买到的是另一样东西：**这个窗口里坐着一个能写文件的 AI**，
而从「右键 → 打开方式」进来时，用户的意图**通常只是看一眼**。

> 这道闸的理由不是「我们改不了」，是「**在我们还不确定你想不想让我们改的时候，先别改**」。

## 4. 接管横条（工作台顶部 · 解锁之后才出现）

**字面本身没改**，改的是**出现时机** —— 这是这一批唯一的形制变化。

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 文 | 这是一个**普通目录** —— 我们**没往里写任何东西**。要预览 `.dc.html` 设计稿的话，得先放几样工具文件进来。 | This is a **plain folder** — we haven't written anything into it. To preview `.dc.html` design files we need to put a few tool files in first. |
| 钮 | 接管为设计项目 | Set up as a design project |
| 钮（进行中） | 正在接管… | Setting up… |

**接管成功的 toast**：标题「已接管为设计项目」，正文「部署了预览壳与运行时副本，现在 .dc.html 能预览了」。

### ⚠️ 请你认：两条横条**一次只出一条**，顺序是「先只读、再接管」

```
随手打开一个目录
   ↓
［只读预览 —— 我们默认不动它们］ ［开始编辑］      ← 只有这一条
   ↓ 点了「开始编辑」
横条退场，toast 说「原文件夹不会多出任何文件」
   ↓ 如果这个目录里有 .dc.html 要预览
［这是一个普通目录 —— 我们没往里写任何东西］ ［接管为设计项目］   ← 这时才出
```

理由：**接管必然蕴含可编辑**（它要写 `project.json`，那一下就解锁了）。
在还只读的时候摆一颗「接管为设计项目」，等于让人**先点一个会往他目录里写 750 KB 的按钮，
来解除一个「不动你文件」的保护** —— 顺序反了。

两条横条答的是两个不同的问题，而它们**不是同一个层级**：
「我们能不能动你的文件」在前，「要不要放工具文件进来预览设计稿」在后。

**什么时候出现**：在一个还没接管的目录里，从文件列右键 / 列头 `⋯` 点「新建稿件…」。
接管成功后这一段消失，换成原来的文件名表单。

| 位 | 中 | 建议 EN |

| 标题 | 先接管这个目录？ | Set this folder up first? |

**四行表 + 合计行**（左列标签 / 中列字节 / 右列为什么）：

| **合计 / Total** | **约 750 KB** | 17 个文件 · 都是生成物，删掉下次打开会重建 / 17 files · all generated; delete them and they're rebuilt next time |

| 位 | 中 | 建议 EN |
| --- | --- | --- |
| 正文 2 | **你原来的文件一个字节都不会被改**，`.gitignore` 也不动 —— 排除规则写在我们自己那边。快照、评论、回收站这些也都不在这个目录里。 | **Your own files are not modified at all**, and `.gitignore` is left alone — ignore rules live on our side. Snapshots, comments and the trash aren't in this folder either. |
| 正文 3 | 不接管只建那一份行不行？**建一份稿本身就要写上面那 226 KB 的运行时副本**，而预览壳不在的话属性面板和点选会 404 —— 那等于写了 226 KB 只换来半个能用的编辑器，所以这里不给那条路。只是**看、改已有的文件、圈给 AI** 一直不需要接管。 | Can't you just create the one file? **Creating it already writes those 226 KB of runtime files**, and without the preview shells the properties panel and picking would 404 — that's 226 KB for half a working editor, so we don't offer that path. **Viewing, editing existing files and sending selections to the AI** never need this. |

| 钮 2（主） | 接管并继续 | Set up and continue |

**两条请你认的做法**：

① **为什么是两段，而不是在表单上加一条横条。** 表单里按 Enter 就提交，
**横条是能被 Enter 跳过去的** —— 那就又回到「写完才知道」。
两段式让那一问**必须被看见一次**，而接管是每个目录一次的事，之后这一段不再出现。

② **为什么没有第三颗「只建这一份，先不接管」。** 算一下就知道那个选项没意义：
它已经要写 226 KB 的运行时副本，而接管总共约 750 KB。
> **那颗按钮用全部功能换了几乎没有的代价。**

## 9. 顺带请你认一处**改字面的建议**：「忘掉这个项目」那个二次确认

这一条不在上面那一批里 —— 它是**抽字面的时候对照代码发现的**，
而它现在**和实际行为对不上两处**，第一处是严重的那种。

**首页每一行 `⋯` 菜单 → 「忘掉这个项目…」→ 第一下摊开的那段确认，现在写的是：**

```
会删掉：这条打开记录 + 我们为它存的版本历史（git 兜底仓库）。退不回来。
你目录里的文件一个字节都不动；目录里那份 .umbrastudio/ 也不动。
                          ［真的忘掉］
```

### 问题一（严重）：它把**要删的东西说少了**

那一句只说「版本历史（git 兜底仓库）」，而实际删掉的是**整个那条记录目录** ——

| 真的会删 | 字面提到了吗 |
| --- | --- |
| 这条打开记录 | ✅ |
| git 兜底仓库 | ✅ |
| **稿件快照（所有版本历史）** | ❌ |
| **节点评论** | ❌ |
| **回收站里的东西** | ❌ |
| **模板** | ❌ |
| **没落盘的暂存草稿** | ❌ |
| **AI 会话（全部对话记录）** | ❌ |

> **一个二次确认把要删的东西说少了，比没有确认糟** ——
> 用户是照着那句话按下「真的忘掉」的，而他以为保住的评论和会话已经没了。

### 问题二：「目录里那份 `.umbrastudio/` 也不动」指着一个**不存在的东西**

这一批之前项目目录里确实有一个 `.umbrastudio/`，现在**没有了**（都搬进软件自己的目录了）。
而这句话留在这儿更坏：它**反过来暗示我们往他目录里放了一个** ——
恰恰是我们花两天移走的那件事。

⚠️ 唯一还可能存在的是**很早以前**写下的旧那一份（我们拍板过「旧目录留在原地，不迁也不删」）。
而「忘掉」这件能力的回执里**已经有一个专门报它的字段**，所以这句话该**跟着那个字段说，而不是写死**。

### 建议改成

```
会删掉我们为它存的全部历史，退不回来：
  · 稿件的版本快照 · 节点评论 · 回收站 · 模板 · 没落盘的草稿 · AI 会话
  · 这条打开记录 · 以及我们为它单独存的 git 兜底仓库

你目录里的文件一个字节都不动 —— 删的全是我们自己目录里的东西。
                          ［真的忘掉］
```

（只有旧那一份还在时，再追一句：`你目录里还有一份很早以前留下的 .umbrastudio/，这一件不碰它。`）

**建议 EN**：

```
This permanently deletes everything we've stored for it:
  · version snapshots · node comments · trash · templates · unsaved drafts · AI chats
  · this entry in Recent · and the separate git backup we keep for it

None of your own files are touched — everything deleted lives in our own folder.
                          [ Forget it ]
```

**请你认两件**：
① 那一串要删的东西，**列成一条一条的，还是并成一句话**？（我们倾向列出来 ——
它是不可逆的，而「AI 会话也会删」是最容易让人意外的一条）
② 「你目录里的文件一个字节都不动」这句**要不要留在确认里**。
我们倾向留 —— 它是整个确认里唯一的好消息，而且正面回答用户最担心的那件事。
