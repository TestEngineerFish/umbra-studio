## 二、`.gitignore` 走了第三条路（不是你提的那条，但它更好）

你裁的是「**两处统一成不动 `.gitignore`**」。照字面做的话有个代价你可能没看到：
那 17 个生成物会在用户自己的 git 仓库里变成**未跟踪文件** ——
`git status` 一屏红。反向验证的读数就是那一屏：

```
?? .umbradesign/select-bridge.js · ?? IconGlyph.dc.html · ?? _ds-tool/tokens.css
?? icons.js · ?? index-data.js · ?? index.dc.html
?? react-dom.production.min.js · ?? react.production.min.js · ?? support.js
```

所以走了第三条：**写进那个仓库的 `.git/info/exclude`**。它
**只在本机生效、不进版本、不是用户的文件** —— 我们在 git 兜底仓库里用的就是这一招。

> **「不要改用户的文件」和「不要让他的 git 变脏」不是一对矛盾** ——
> git 自己就留了一个本机专用的排除位置。

四条边界（**失败一律是「没帮上」，不是「报错」** —— 排除规则写不进去不该让接管失败）：

| 情况 | 做什么 |
| --- | --- |
| 不在 git 仓库里 | **什么都不写** |
| `.git` 是**文件**（worktree / 子模块） | 按里面的 `gitdir:` 指向去找真 GIT_DIR |
| 那个指向不存在 | **不写**，并说出原因 |
| 写不下去（只读 / 权限） | **不写**，并说出原因 |

⚠️ 那第二条不处理的话后果很具体：代码把 `.git` 文件**当目录**用，
`mkdir -p` 会在他的项目里**凭空建出一个 `.git/info/`**。判据里有这一条。
⚠️ 排除清单里**刻意不含 `project.json`** —— 那是「这个目录是设计项目」的标记，
**它该进版本**（同事 clone 下来才知道这是个设计项目）。
> 排除清单和部署清单不是同一张：**有一样东西我们放进去、而且希望它留下。**

「忘掉这个项目」时顺手撤掉那一段（只删带我们标记的那一段，`info/exclude` 里别人写的一个字不动）。

### 1 ·「取消 Esc」里的 Esc 要画成键帽 —— 但它在三个弹窗里都有

你说的是对的（现在是「取消 Esc」连写）。但这不是改一句话，是**加一个键帽样式**，
而键帽在我们这儿会出现在不止这里：弹窗的「新建 ⏎」、页签菜单的「⌘⌫」、
目录右键的「F2」/「⌘P」，现在都是 `hint` 那种小字。

**所以请你定一次，一次定完**：键帽长什么样（底色 / 边框 / 圆角 / 字号），
以及**哪些地方用它**（只有弹窗底部的按钮？还是所有菜单项后面的快捷键都换成键帽？）。
我们不自己定一个版本出来 —— 那会变成第二套形制。

### 2 · 排除规则那一句要不要出现在界面上

你裁「文案两处都写成『不动 `.gitignore`』」，并问要不要补一句说明。我们现在写的是：

> **你原来的文件一个字节都不会被改**，`.gitignore` 也不动
> —— 这个目录在 git 仓库里的话，排除规则记在本机那份 `.git/info/exclude` 里（不进版本）。

**两种都说得通，请你定**：

| | 字面 | 代价 |
| --- | --- | --- |
| **甲**（现在这版） | 带上「记在 `.git/info/exclude` 里」 | 多一个技术名词。但它回答了一个会被问的问题：「那这些生成物会不会污染我的 git」 |
| **乙** | 只说「`.gitignore` 也不动」，不提我们写哪儿 | 短。但用 git 的人多半会去查那 17 个文件为什么不出现在 `git status` 里，**而查不到答案比多一个名词糟** |

我们倾向**甲**，理由是：这一整批的主题就是「把我们动了什么照实说出来」，
而 `.git/info/exclude` **确实是我们动的一个地方** —— 不说它，就又是一次「只说了真的那半」。

### 3 · 顺带一个请你知道的（不用裁）

「忘掉这个项目」的条数（「AI 会话（12 段）」那种）**这一期没带**。
