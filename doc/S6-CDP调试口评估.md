# `remote-debugging-port` 评估（geek-99 2026-10-24 要的三件，**只评估不动手**）

**结论先说**：这个口今天**只剩风险没有收益** —— 它唯一的产品消费者（体检走自带 Chromium）
在 C3 已经整条删了。而它开放的东西比预想的多：**主窗口、preload 的桥、本地 API 令牌**。

---

## ① 端口绑在哪个地址

**`127.0.0.1`，不是 `0.0.0.0`。** 实测（用户那份 10-22 的包正在跑，只读）：

```
pid 88752 → 127.0.0.1:51475 (TCP)   ← CDP（/json/version 回 Chrome/152.0.7977.130）
pid 88752 → 127.0.0.1:51481 (TCP)   ← hub（本地 API）
pid 88752 → 127.0.0.1:51567 / 51588 ← 项目服务 / 插件服务
```

所以**局域网里的别人碰不到**，威胁面是「**本机的其它进程**」。
⚠️ 但这不是一句可以放心的话：本机其它进程包括用户装的任何一个 App、任何一段脚本 ——
而我们自己的插件沙箱就是按「本机进程也不可信」设计的（Node 权限模型 + 网络桩）。
> **同一台机器上的另一个进程，在插件那一层被当成不可信，在这一层被当成可信。**

## ② DevTools 能接上哪些目标 —— **不只有体检窗口，主窗口也在里面**

`curl http://127.0.0.1:51475/json/list` 实测 **4 个目标**：

| 目标 | 类型 | 是什么 |
| --- | --- | --- |
| `http://127.0.0.1:51481/__app/` | page | **主窗口（工作台本体）** |
| `…/__plugin/com.umbra.markdown/index.html` | iframe | 插件 A 面 |
| `…/__plugin/com.umbra.markdown/outline.html` | iframe | 插件 A 面 |
| `about:blank#umbrastudio-check` | page | 体检用的隐藏窗口 |

**而接上主窗口能拿到什么，是实测不是推断**（只读探针，没调任何会写的东西）：

```
有桥: true
桥上的方法: pickDirectory · revealInFinder · openExternal · notify · setTitle ·
           pathsForDrop · openInNewWindow · capabilities · onEvent · kind
有令牌: true    令牌长度: 32
hub: http://127.0.0.1:51481/
```

⚠️⚠️ **拿到那个 32 字符的令牌就等于拿到 `/__ud/*` 的全部能力** ——
而那正是 **Q42 / issue #30** 当年要堵的那条路（「本机任何进程不带令牌 `GET /__app/`
就能拿到真令牌 → 调 `/__ud/*` 全部能力，白名单整体绕过」）。

> **一道闸守住了「令牌怎么到页面」，而另一个开关把「页面本身」开放了出去。**
> 两者在威胁模型上是同一件事，而它们在代码里隔着 150 行、属于两个不同的功能 ——
> 这就是为什么 Q42 结案之后没人发现它被绕过了。

⚠️ 还能碰到 **preload 暴露的桥**：`pickDirectory`（弹目录选择器）·
`revealInFinder` / `openExternal`（**用默认程序打开任意路径**）· `pathsForDrop`。
`openExternal` 这一件尤其重：它是「让系统去打开一个东西」，而 issue #110 记着
`open <path>` 对文件是「用默认程序打开」。

## ③ 能不能只给体检窗口 / 按需开

**不能「只给一个窗口」** —— `remote-debugging-port` 是 **浏览器级（整个 Chromium 实例）**
的开关，开了就是全部目标。Chromium 没有「只暴露某个 target」的开关。
（`/json/list` 实测把主窗口和两个插件 iframe 都列出来了，就是这个性质的直接读数。）

**而「按需开、用完关」也不成立**：`--remote-debugging-port` 必须在
`app.commandLine.appendSwitch` 阶段（ready 之前）给，**运行期开不了也关不掉**。

### ⚠️⚠️ 但有一条比「怎么收窄」更直接的路：**这个口今天没有消费者了**

`createCheckWindow()` 的注释自己写着「标记：核心 `render.ts` 按它找体检页（`CDP_PAGE_MARK`）」——
而 **`render.ts` 在 C3（M16-7c-2a）删了**，`render_check` / `check` / `check_status` 三件一起删。
核过（`git grep`，不是推断）：

| 读 `UMBRASTUDIO_CDP` 的地方 | 性质 |
| --- | --- |
| `shell/main.mjs:235` | **写**它的那一行（自己） |
| `shell/shelltest.mjs:102 / 434` | 两条判据 |
| `doc/00` / `doc/01` / `doc/12` 若干处 | 历史记录 |
| **`server/` 下** | **零命中** |

于是今天的实际状态是：
· `UMBRASTUDIO_CDP` 这个环境变量**没有产品读者**；
· `about:blank#umbrastudio-check` 那个隐藏窗口**白开着**（一个额外的渲染进程）；
· `remote-debugging-port=0` 留着，**只换来上面那些风险**。

> **一个开关的理由消失之后，它不会自己关掉。**
> ⚠️ 而更要留意的是：**接下来第一个用上它的人会给它一个新的存在理由** ——
> 我今天就是那个人（`packtest` 的新进门方式接到了这个口上）。
> 所以这件事要现在定，不要等它长出第二个消费者。

### 四条路（代价都写出来，geek-99 定）

| 路 | 做什么 | 代价 |
| --- | --- | --- |
| **甲** | **整个关掉**：删 `remote-debugging-port`、删 `createCheckWindow`、删 `UMBRASTUDIO_CDP` | `packtest` 第二关刚换上的进门方式**又没了** —— 要再换一次（见下）。`shelltest` 两条判据要删 |
| **乙** | **只在开发/测试时开**：按环境变量（如 `UMBRASTUDIO_AUTOTEST_LOG` 已置位）决定要不要 `appendSwitch` | 用户那份一行调试口都不开（最干净）。⚠️ 代价是 `packtest` 测的产物**跑在一个和用户不完全一样的开关组合下** —— 而这正是 fuse 那件事刚教过的（「测的不再是发出去那一份」） |
| **丙** | 保持现状 | 上面那些风险照旧，而换来的收益**是零**（没有产品消费者） |
| **丁** | 关掉它，`packtest` 第二关改走**不需要 CDP** 的证据 | 要重做一次：`UMBRASTUDIO_AUTOTEST_LOG` 里已有 `hub`，那条路能验「hub 起没起、令牌对不对、共享库在不在」（HTTP）；但**验不了「页面里有什么」**（令牌经 preload 到了页面 / 地址里不带令牌 / 目录树 78 条）—— 那三条要页面 |

**我的建议：乙。** 理由是三件事的权衡，而不是「哪个更安全」：
· 用户那份**不该**开着一个能接管主窗口的口（②的实测就是理由）；
· 而 `packtest` 的价值在「**在干净机器上真跑一次**」，它要页面那几条；
· 乙的代价（开关组合不同）**可以被一条判据钉住**：在 `packtest` 里断言
  「**没有 `UMBRASTUDIO_AUTOTEST_LOG` 时，产物不开调试口**」——
  这样「用户那份不开」这件事本身就有读数，而不是靠记得。
⚠️ 如果选甲或丁，`packtest` 第二关会从 10 条掉到 7 条，**那三条要照实记进分母**（不许悄悄少掉）。

## 顺带：一条和它相邻的既存事实

`--mcp` 模式**刻意不开 CDP**（issue #191），理由写在 `main.mjs:78` ——
`DevToolsActivePort` 是 `userData` 里的**一个文件**，两个进程都写的话后起的覆盖先起的。
⚠️ 那条注释说「这一条今天不一定炸（体检只在主实例里发起）」——
**体检没了之后它更不会炸，但那个覆盖的结构还在**；而现在 `packtest` 从那个文件读端口，
于是「两个进程写同一个文件、而读的人不知道」这件事**有了第一个真读者**。
（我这一轮已经踩到它的一个近亲：autotest 日志是追加的，读「最后一行」拿到的是上一个实例的。）
