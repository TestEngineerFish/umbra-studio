# Windows 真机验收步骤（M9-6）

> 给拿到 Windows 机器的人照着做。**不需要装开发环境** —— 只要解压、双击、看几处输出。
> 这一份是「换台机器还能不能用」的验收，不是功能测试。
>
> 为什么非要真机：`packtest` 在 mac 上只验得到 win 产物的**结构关**（17/17），
> 「exe 能不能起、核心子进程能不能起、状态写到哪里」这三样**只有真机答得出**。
> mac 打包那一轮的三条缺陷全是这一类（`00` §六十三），开发模式下一条都测不出来。

---

## 零、准备

| 要什么 | 说明 |
| --- | --- |
| 一台 Windows 10 / 11（x64） | arm64 机器也行，换用 arm64 那个包 |
| `Umbra Studio-0.1.0-win-x64.zip` | 在 `shell/out/` 下；我会单独发给你，或从仓库的 Releases 取 |
| 一个装着几份 `.dc.html` 的目录 | 没有也行，第 4 步会现建一个 |

**不要**装 Node、不要装 git、不要装 Chrome —— 这三样都是**故意不装**的：
产品的承诺是「用户不是开发者也能用」，装了就测不出「少了它会怎样」。

---

## 一、解压与首次启动

1. 把 zip **解压到一个普通目录**（例如 `D:\UmbraStudio`）。
   ⚠️ **不要放在 `C:\Program Files` 下** —— 那里默认只读，而我们要验的正是
   「可写状态有没有错写到程序目录里」。放在 Program Files 会让这个缺陷被系统挡住而看不见。
2. 双击 `Umbra Studio.exe`。
3. Windows 可能弹「Windows 已保护你的电脑」（SmartScreen）——
   **这是预期的**（我们还没做 Windows 代码签名），点「更多信息」→「仍要运行」。

### 要看的第一处输出：窗口标题栏

| 看到 | 说明 |
| --- | --- |
| 打开了一个窗口，标题是「Umbra Studio」，里面是项目列表（可能是空的） | ✅ 第 1 关过 |
| 窗口一闪就没了 | ✗ 记下来：**主进程起不来**。按第五节取日志 |
| 窗口在但里面是白的 / 一直转圈 | ✗ 记下来：**核心子进程起不来**（这是最可能的一条，见第五节） |
| 窗口里写着「**这个页面还拿不到访问令牌**」 | ✗ 记下来：**令牌注入那一步在 win 上坏了**。这是 2026-09-28 新加的一条路（`00` §一一二）：桌面版的令牌由主进程经 `additionalArguments` 交给 preload，**不走地址**。那一屏自己会说「先完全退出再打开一次」—— 请照它说的做一次，**如果第二次还是这样，这就是一条真缺陷**，按第五节取日志 |

---

## 二、核心子进程有没有起来（最要紧的一关）

窗口里应该能看到「导入目录」这类按钮。**按 `Ctrl+Shift+I` 打开开发者工具**
（我们没关掉它），切到 **Console**。

### 要看的输出

```
（正常）Console 里没有红色报错；Network 里有一条 127.0.0.1:<端口>/__app/ 是 200
（不正常）Failed to fetch / ERR_CONNECTION_REFUSED / net::ERR_EMPTY_RESPONSE
```

`ERR_CONNECTION_REFUSED` = **核心（那个 Node 子进程）没起来**，这是 win 上最可能出的一条。
请把 Console 里所有红色的行**截图**，再按第五节取主进程日志。

---

## 三、状态写到哪里（mac 上逼出过的那一条）

这一关验的是 `00` §63.1 那条：**可写状态必须写到用户数据目录，不能写进程序目录**。

1. 在地址栏（资源管理器）输入 `%APPDATA%` 回车
2. 应该有一个 `Umbra Studio` 文件夹，里面有 `.umbrastudio\`（可能还有 `Cache` 之类）

| 看到 | 说明 |
| --- | --- |
| `%APPDATA%\Umbra Studio\.umbrastudio\` 存在 | ✅ 第 3 关过 |
| 它不存在，而**解压目录**里多出了 `.umbrastudio\` | ✗ **这就是那条缺陷**：状态写进了程序目录。记下来 |

---

## 四、走一遍主流程

1. 点「导入目录」，选一个目录（可以现建一个空的，例如 `D:\测试项目`）
2. 进去之后：
   - **左边**应该列出目录里的文件
   - 在左边点一下任意文件，**中间**应该显示它（`.md` 显示排版、图片显示图、`.dc.html` 显示稿）
   - 右边是聊天栏（没配 AI 的话发不出消息，**这是预期的**，不算缺陷）
3. 新建一份稿：项目名 ▾ →「新建稿件…」→ 随便起个名 → 确定
4. 打开它，按 `⌘E`（win 上是 **Ctrl+E**）展开编辑栏，应该看到
   **「点选 / 评论 / 编辑」三颗钮**
5. 切到「评论」档，点稿里任意元素 —— 元素下面应该弹出一个评论框

### 要看的输出

| 关 | 期望 |
| --- | --- |
| 4-1 | 目录列出了文件 |
| 4-2 | 点文件后中间显示出内容（不是白屏） |
| 4-3 | 新建稿件成功，文件真的出现在那个目录里（用资源管理器确认） |
| 4-4 | Ctrl+E 能展开编辑栏，三颗指针钮都在 |
| 4-5 | 评论档点元素能弹出评论框 |

第 4-3 那一步做完，**那个目录里应该多出一个 `.git` 文件夹**（M9-7 自动记版本）。
在那个目录里开一个终端跑 `git log --oneline` 应该看到一条「写入 …」的提交 ——
⚠️ 如果机器上**没装 git**，这一条不会有，**那是预期的**（git 是兜底，没有也照常用）。

## 五、出问题时怎么取日志

主进程的输出不在开发者工具里。两种取法：

**A. 从命令行启动（推荐，能直接看到所有输出）**

在解压目录里开 PowerShell，然后：

```powershell
.\"Umbra Studio.exe" | Tee-Object -FilePath run.log
```

> 窗口会照常打开，所有主进程输出同时写进 `run.log`。把这个文件发我。

**B. 只要核心那一段**

核心子进程的日志会带 `[core]` 前缀。如果 A 跑不了，至少截图 Console（第二节）。

### 最可能的四条，以及它们长什么样

| 现象 | 大概是什么 |
| --- | --- |
| `ERR_CONNECTION_REFUSED`，`run.log` 里有 `spawn ... ENOENT` | 核心找不到要起的可执行文件（打包路径在 win 上拼错了） |
| `run.log` 里有 `EPERM` / `EACCES` / `read-only` | 往程序目录写东西了（第三节那条缺陷） |
| 窗口白屏、Console 里 404 `/__app/` | 前端资源没进包（`files` 配置漏了） |
| 「拿不到访问令牌」那一屏，Console 里没有红字 | `additionalArguments` 那条路在 win 上没走通（`00` §一一二）。`run.log` 里应该能看到主进程起了服务、拿到了端口 —— **服务起来了但页面拿不到令牌**就是这一条 |

## 六、做完请回报这些

1. 六个关分别过没过（一、二、三 各一关，四是五个小关）
2. `%APPDATA%\Umbra Studio\` 里有什么（截图目录即可）
3. 出错的话：`run.log` + Console 截图
4. 顺带一句感受：**启动到能用大概几秒**（mac 上约 2–4 秒，win 上慢很多的话是另一条要查的）

## 七、这一轮不用验的

- **代码签名 / SmartScreen**：Windows 签名证书还没买，弹警告是预期的（M9-5 只做了 mac）
- **AI 对话**：要配 key，和「换台机器能不能用」无关
- **插件市场的购买**：后端还没接（`00` §100.1 明说没接）
- **性能 / 大项目**：这一轮只验「能不能用」，不验「快不快」
